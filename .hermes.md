# Purpose

Unofficial API-key-free Python client and CLI for Zomato/District restaurant, review, offer, rating-trend, dish, event, nightlife, and nearby party discovery.

# Current State

- Python package uses a `src/` layout; CLI entry point is `zomato`.
- Main client: `src/zomato/client.py`; CLI: `src/zomato/cli.py`.
- Persistent Zomato CSRF/cookies live at `~/.zomato-py/session.json`.
- Approved user coordinates live separately at `~/.zomato-py/location.json`.
- Cross-platform browser geolocation is implemented through a temporary IPv4-loopback server (`127.0.0.1`), explicit browser permission, a random one-use state, an exact required callback Origin, strict mutually-exclusive payload schemas, content/body validation, and a single callback.
- `zomato location` exposes `detect`, `show`, `set`, `clear`, and `search` subcommands.
- `zomato party` resolves coordinates in exact order: (1) complete explicit `--lat`/`--lng` pair, (2) saved approved location, (3) browser detection. A partial explicit pair is an error; `--no-location-detect` disables step 3.
- Recursive District individual-page crawling remains integrated into `zomato party` by default; `--no-crawl` opts out.
- All geolocation changes are intentionally uncommitted.

# Decisions

- Explicit coordinates must be supplied as a complete pair and always outrank persisted or detected coordinates.
- A saved approved location outranks browser detection, so repeated party searches do not re-prompt.
- Browser location is opt-in at the browser permission prompt and may be disabled for party discovery with `--no-location-detect`.
- Persist only successfully approved callbacks. Permission denial, unavailable services, timeouts, invalid callbacks, and browser-launch failures must leave saved data unchanged.
- Store only latitude, longitude, optional accuracy, source, and approval timestamp. Use atomic same-directory replacement and POSIX mode `0600` for the file / `0700` for its directory where supported.
- Bind callbacks only to IPv4 loopback; do not log HTTP requests or coordinates.
- Require callback Origin to equal the generated `http://127.0.0.1:<port>` origin exactly; missing Origin, `localhost`, and all other origins are rejected without consuming state.
- Keep the callback protocol minimal: success is exactly `{state, coordinates}` with required numeric latitude/longitude and optional numeric accuracy; error is exactly `{state, error}` with an integer code only. Unknown fields and mixed success/error payloads are rejected.
- District main `/events` data alone is incomplete; party discovery continues to crawl venue rails and discovered event pages by default.
