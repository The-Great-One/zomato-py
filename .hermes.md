# Purpose

Unofficial API-key-free Python client and CLI for Zomato/District restaurant, review, offer, rating-trend, dish, event, and nightlife discovery.

# Current State

- Python package uses `src/` layout with CLI command `zomato`.
- Main client: `src/zomato/client.py`; CLI: `src/zomato/cli.py`.
- Persistent Zomato CSRF/cookies live at `~/.zomato-py/session.json`.
- Recursive District individual-page crawling is verified and integrated into `zomato party` by default.
- District venue HTML is client-rendered. The implementation reproduces its guest web request to `/gw/consumer/event/venue-page-web` and recursively crawls events discovered from venue rails.
- Delayed crawler-review fixes are implemented locally and intentionally uncommitted: venue-only crawls make no event-detail requests, ambiguous title-only enrichment is rejected, and `DISTRICT_GUEST_TOKEN` is resolved per request.

# Decisions

- District main `/events` data alone is incomplete; party discovery must crawl venue rails and their event detail pages.
- Do not hardcode venue names such as Avatar. Discover venues/events from direct pages, District rails, or Zomato URLs.
- Keep `--no-crawl` as an opt-out because full recursive discovery performs dozens of HTTP requests.
- Treat venue HTML as client-side-only and use District's guest venue API for actual detail data.
